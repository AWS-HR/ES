# 仕様（ES採点システム）

コードを変更するときの基準となる仕様です。仕様の検討は採用チームとClaudeのチャットで行い、決まった内容をこのファイルとコードに反映します。背景や経緯は提案書（「ES自動採点システム 提案書（株式会社アワーズ）」）を参照してください。

最終更新：2026-10-21

## 目的と前提

- 新卒（総合職）・経験者採用の書類選考で、ES（PDF）をAIが採点し、担当者の判断を補助する
- AIの点数だけで合否を決めない。合否は採用担当者が判断する
- 採点は会社契約のClaudeアカウントで行う（社内AI活用ガイドライン第3章・第5章）。TASKの承認（第6章）までは、ダミーのESだけを使う

## 全体の流れ

1. 担当者が、選考区分ごとのドライブのフォルダにESのPDFを入れる
2. Claudeのスケジュールタスクが決まった時刻（現在は毎日6:00ごろ）に起動する
3. ClaudeがES採点スキルに従って採点し、採点結果・根拠詳細シートに書き込む（1回の上限は10件。残りは次の定時採点で採点する）。実行の記録は採点記録シートに残す
4. 担当者が閲覧アプリで結果を確認し、ステータスとメモを入力する

## スプレッドシート「ES自動評価アプリ」（7シート）

GASは単独のApps Scriptプロジェクトで、`src/Config.gs` の `SPREADSHEET_ID` でこのスプレッドシートを指定して読み書きする。スプレッドシートにメニューは表示されないため、初期設定（setupSpreadsheet）と再計算（recalculateTotals）はApps Scriptのエディタから実行する。

| シート | 内容 | 書き込むもの |
| --- | --- | --- |
| 採点結果 | 応募者1人＝1行（総合点・ランク・総評・ステータス・メモなど） | Claude（追記のみ）、閲覧アプリ（ステータス・メモ） |
| 根拠詳細 | 応募者×評価軸＝1行（段階・得点・判定理由・引用） | Claude（追記のみ） |
| 選考区分 | 区分ごとのESフォルダ・評価基準・設問セット・状態（受付中／準備中／終了） | 管理者 |
| 評価基準 | 基準名ごとの軸・配点・ルーブリック。RANK_A / RANK_B 行はランクの下限点 | 管理者（見直すときは新しい基準名で追加） |
| 設問 | 設問セットごとの設問と、主に読み取る軸ID | 管理者 |
| 権限 | 閲覧アプリの利用者と役割（管理者／評価者／閲覧者／停止） | 管理者 |
| 採点記録 | Claudeが採点を実行した記録（処理中／完了／エラー、結果の件数） | Claude |

列の定義は `src/Code.gs` の `HEADERS` が正です。

## 評価基準（新卒総合職_v1）

経験者採用も書類選考では同じ基準を使う。設問の対応だけが異なる（設問セット：新卒_v1／経験者_v1）。

| 軸ID | 評価軸 | こころ | 配点 |
| --- | --- | --- | --- |
| people | 人が好き・出会いを大切にする | 思いやり | 25 |
| purpose | 意味・目的を考える力 | 素直 | 20 |
| axis | 自分の軸 | 前向き | 20 |
| self_esteem | 自己肯定感 | 思いやり | 15 |
| feedback | 他者の意見を受け入れる力 | 素直 | 10 |
| pdca | PDCA・改善する力 | 前向き | 10 |

- 各軸は5段階。得点 ＝ 配点 × 段階 ÷ 5。総合点は合計を四捨五入（100点満点）
- 関連する記述がない軸は「記述不足」とし、段階3として計算する
- ランク：80点以上 A、65点以上 B、それ未満 C
- 評価に使わない情報：本籍・出生地、家族、住居、宗教・思想・信条、性別・年齢・容姿・健康、学校名、前職の会社名、経歴の長さ
- ルーブリックの文言は `src/Code.gs` の `SEED_CRITERIA`（初期値）にあり、運用中は評価基準シートが正

## 閲覧アプリ「ESチェッカー」（GAS Webアプリ）

- 一覧：採点の状況（未採点件数・採点中かどうか・前回の結果・自動採点の時刻）、絞り込み（区分・ランク・ステータス・氏名）、6軸の5段階バーと各軸の得点（例：12/15点）
- 詳細：レーダーチャート、総評・強み・確認したい点、軸ごとの判定理由と引用、ステータス・メモ、PDF表示
- 比較：最大5人のレーダーチャートの重ね表示と軸ごとの点数表（同じ評価基準どうしのみ）。線の種類（実線・破線・点線・長い破線・一点鎖線）で人を見分ける
- 評価軸の並び：すべての画面で「思いやり → 素直 → 前向き」の順にまとめる（人が好き、自己肯定感、目的思考、意見受容、自分の軸、PDCA）。同じこころの中は評価基準シートの「表示順」。並びはコードで固定しているため、評価基準シートの表示順を変えてもこころのまとまりは崩れない
- 権限：権限シートに登録された人だけが使える。ステータス・メモの変更は管理者と評価者のみ
- 総合点・ランクは、表示のたびに根拠詳細の段階から計算し直す

## 自動採点

- スケジュール：毎日6:00ごろ。業務でClaudeを使わない早朝にして、使用量を日中の業務と取り合わないようにする（使用量の測定後に件数を見直す予定）
- 閲覧アプリから採点を始めるボタンは設けない（即時に採点できないため。2026-10-21 決定）
- 採点中のClaudeは使用量の残りを確認できないため、件数で調整する
- 時刻や件数を変えるときは `docs/定時採点タスク.md` を参照
