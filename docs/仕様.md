# 仕様（ES採点システム）

コードを変更するときの基準となる仕様です。仕様の検討は採用チームとClaudeのチャットで行い、決まった内容をこのファイルとコードに反映します。背景や経緯は提案書（「ES自動採点システム 提案書（株式会社アワーズ）」）を参照してください。

最終更新：2026-10-23

## 目的と前提

- 新卒（総合職）・経験者採用の書類選考で、ES（PDF）をAIが採点し、担当者の判断を補助する
- AIの点数だけで合否を決めない。合否は採用担当者が判断する
- 採点は会社契約のClaudeアカウントで行う（社内AI活用ガイドライン第3章・第5章）。TASKの承認（第6章）までは、ダミーのESだけを使う

## 全体の流れ

1. 担当者が、選考区分ごとのドライブのフォルダにESのPDFを入れる
2. Claudeのスケジュールタスクが毎日8時・13時・18時に起動する
3. ClaudeがES採点スキルに従って採点し、採点結果・根拠詳細シートに書き込む（8時・13時は各10件、18時は20件まで。残りは次の定時採点で採点する）。実行の記録は採点記録シートに残す
4. 採点済みのPDFは、ファイル名の頭に「済_」を付ける（未採点と見分けるため）。「要確認」のPDFは名前を変えない。フォルダへの移動は担当者が手作業で行う
5. 担当者が閲覧アプリで結果を確認し、ステータスとメモを入力する

## スプレッドシート「ES自動評価アプリ」（7シート）

GASは単独のApps Scriptプロジェクトで、`src/Config.gs` の `SPREADSHEET_ID` でこのスプレッドシートを指定して読み書きする。スプレッドシートにメニューは表示されないため、初期設定（setupSpreadsheet）と再計算（recalculateTotals）はApps Scriptのエディタから実行する。

| シート | 内容 | 書き込むもの |
| --- | --- | --- |
| 採点結果 | 応募者1人＝1行（総合点・ランク・総評・ステータス・メモなど） | Claude（追記のみ）、閲覧アプリ（ステータス・メモ） |
| 根拠詳細 | 応募者×評価軸＝1行（段階・得点・判定理由・引用） | Claude（追記のみ） |
| 選考区分 | 区分ごとのESフォルダ・評価基準・設問セット・状態（受付中／準備中／終了） | 管理者 |
| 評価基準 | 基準名ごとの軸・配点・ルーブリック。RANK_A / RANK_B 行はランクの下限点 | 管理者（見直すときは新しい基準名で追加） |
| 設問 | 設問セットごとの設問と、主に読み取る軸ID | 管理者 |
| 権限 | 閲覧アプリの利用者と役割（管理者／評価者／閲覧者／停止） | 管理者 |
| 採点記録 | Claudeが採点を実行した記録（処理中／完了／エラー、結果の件数） | Claude |

列の定義は `src/Code.gs` の `HEADERS` が正です。

## 評価基準（新卒総合職_v3）

現在使う基準は新卒総合職_v3。経験者採用も書類選考では同じ基準を使う。設問の対応だけが異なる（設問セット：新卒_v1／経験者_v1）。軸と配点はv1と同じ。

| 軸ID | 評価軸 | こころ | 配点 |
| --- | --- | --- | --- |
| people | 人が好き・出会いを大切にする | 思いやり | 25 |
| purpose | 意味・目的を考える力 | 素直 | 20 |
| axis | 自分の軸 | 前向き | 20 |
| self_esteem | 自己肯定感 | 思いやり | 15 |
| feedback | 他者の意見を受け入れる力 | 素直 | 10 |
| pdca | PDCA・改善する力 | 前向き | 10 |

- 各軸は5段階。得点 ＝ 配点 × 段階 ÷ 5。総合点は合計を四捨五入（100点満点）
- 関連する記述がない軸は「記述不足」とし、段階3として計算する
- ランク（新卒総合職_v3）：91点以上 S、81〜90点 A、66〜80点 B、65点以下 C。評価基準シートの RANK_S / RANK_A / RANK_B 行で決める（v1・v2 は80点以上 A、65点以上 B、それ未満 C で、Sはない）
- ランクの区切りは採点（各軸の段階）を変えないため、例外として v3 の行を更新した（2026-10-23）。表示は根拠詳細から毎回計算するので、v3 で採点済みの結果にも新しいランクが表示される
- 評価に使わない情報：本籍・出生地、家族、住居、宗教・思想・信条、性別・年齢・容姿・健康、学校名、前職の会社名、経歴の長さ
- 理念の言葉（Smile、とき、3つのこころなど）をなぞっているだけでは加点しない。本人の具体的な経験と本人の言葉で判断する。「動物・パークが好き」だけでは評価しないが、動物を通じて人の笑顔・学び・いのちの大切さにつなげて語っていれば目的思考・自分の軸の根拠にしてよい。違いを尊重し、だれもが過ごしやすいよう配慮した行動は「人が好き」の根拠にしてよい（スキルの採点ルール）
- ルーブリックの文言は `src/Code.gs` の `SEED_CRITERIA`（初期値）にあり、運用中は評価基準シートが正

### v2からv3で変えたこと（2026-10-23）

過去のES（個人情報を伏せたもの）20件をv2で採点し、実際の選考結果と比べた。内定・入社者の平均86.7点、ミスマッチの平均77.9点。書類選考で見送ったESの所感（4件）に共通する点を、軸と配点は変えずに見るポイント・段階の文言と採点ルールに反映した。二次・最終選考のミスマッチは面接で分かる要素が大きいため、調整の対象にしない。

| 所感 | 反映先 |
| --- | --- |
| アワーズの社員ではなく、アドベンチャーワールドで働くことだけを書いている | 目的思考・自分の軸：パークで働くことだけなら段階3が上限 |
| 「明確になった」と書いているのに中身が薄い | 自分の軸：言葉だけで判断せず、中身が薄ければ段階3が上限 |
| 価値観が凝り固まっていそう | 意見受容：自分の考えだけが正しいという書き方は段階2 |
| 設問に答えていない（きっかけがない） | 採点ルール：設問に答えていない回答は段階4以上の根拠にしない |
| 文末にかけて話がずれる、意味が不可解 | 採点ルール：話が通っていない回答は段階を上げる根拠にしない |
| 点数が75〜93点に集まり差がつきにくい | 採点ルール：段階5は具体的な行動と結果があり複数の設問で一貫している場合だけ |

### 参考チェック（点数には含めない）

採点結果シートの「文章の気になる点」（誤字・話し言葉・敬語の誤りなど3つまで）、「AI作成の可能性」（ある／ない）、「AI作成の根拠」（「ある」のときだけ、当てはまった特徴を2〜3つ）。閲覧アプリでは、一覧の氏名の下に「AI作成の可能性あり」の目印を出し、絞り込み（ある／ない）と件数の表示を付ける。詳細画面の「参考チェック」には、「ある」の場合に根拠を強調して表示する。AI作成の判定は推定で、確実には見分けられないため、面接で本人の言葉を確かめる参考にとどめる。文字数はES側で上限・下限を設定しているため見ない。

### v1からv2で変えたこと（2026-10-22）

コーポレートサイト（企業理念、求める人財、採用で大切にしていること、代表メッセージ、社長×社員対談、Smile Story、ビジョン）と自社の採用サイトの内容を、各軸の「見るポイント」と段階の文言に反映した。

| 軸 | 追加した観点 | 根拠 |
| --- | --- | --- |
| 人が好き | 周りの笑顔・しあわせを自分の喜びとする行動、感謝を言葉や行動で伝える、人の良さや可能性に目を向ける | 求める人財（思いやり）、創業以来の「人を大切にする。人の可能性を見出す。」 |
| 自己肯定感 | 喜びや感動、成長・達成の実感を素直に自分の言葉で表現する | 求める人財（素直：感受性）、Smile Story「自分が持っていないものは人に与えられない」 |
| 目的思考 | 誰の笑顔やしあわせにつながるかまで考える | 3つのSmile（社員→ゲスト→社会） |
| 意見受容 | 感謝して受け入れ成長につなげる、先人の積み上げを大切にしつつ新しい視点を取り入れる | 求める人財（素直：謙虚さ）、社長×社員対談 |
| 自分の軸 | 大切にしていること（個人理念）と、人のしあわせ・笑顔との重なりを自分の言葉で語る | 採用で大切にしていること（価値観のマッチング）、代表メッセージ（個人理念） |
| PDCA | 失敗から学んで前向きに立て直す、変化や新しいことへの挑戦 | 求める人財（前向き）、対談「変わらないために変わり続ける」、採用サイトの動画 |

v1の行は評価基準シートに残す（v1で採点した結果の表示に使うため）。比較画面は同じ評価基準どうしのみなので、v1とv2の応募者は並べて比較できない。運用中のシートへの追加手順は `docs/導入手順.md` の「評価基準を追加する」。

## 閲覧アプリ「ESチェッカー」（GAS Webアプリ）

- 一覧：採点の状況（未採点件数・採点中かどうか・前回の結果・自動採点の時刻）、絞り込み（区分・ランク・ステータス・氏名）、6軸の5段階バーと各軸の得点（例：12/15点）
- 詳細：レーダーチャート、総評・強み・確認したい点、軸ごとの判定理由と引用、ステータス・メモ、PDF表示
- 比較：最大5人のレーダーチャートの重ね表示と軸ごとの点数表（同じ評価基準どうしのみ）。線の種類（実線・破線・点線・長い破線・一点鎖線）で人を見分ける
- 3つのこころの色分け：思いやり＝朱色、素直＝青緑、前向き＝紫。一覧の見出し・列、詳細の軸カード、レーダーチャートのラベル、比較表で同じ色を使う
- 評価軸の並び：すべての画面で「思いやり → 素直 → 前向き」の順にまとめる（人が好き、自己肯定感、目的思考、意見受容、自分の軸、PDCA）。同じこころの中は評価基準シートの「表示順」。並びはコードで固定しているため、評価基準シートの表示順を変えてもこころのまとまりは崩れない
- 権限：権限シートに登録された人だけが使える。ステータス・メモの変更は管理者と評価者のみ
- 総合点・ランクは、表示のたびに根拠詳細の段階から計算し直す

## 自動採点

- スケジュール：毎日8時（10件）・13時（10件）・18時（20件）。それ以外の時間に採点したいときは、担当者が使用量を確認してから手動で依頼する
- 使用量の目安：ダミーのES 5件で、5時間セッションの使用量が7％（1件あたり約1.4％、10件で約14％）
- 閲覧アプリから採点を始めるボタンは設けない（即時に採点できないため。2026-10-21 決定）
- 採点中のClaudeは使用量の残りを確認できないため、件数で調整する
- 時刻や件数を変えるときは `docs/定時採点タスク.md` を参照
